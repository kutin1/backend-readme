# Backend Grading — Laravel Project

## Организация: HTML Academy

## Студент: Владислав Константинович Кутин

## Описание
Учебный backend‑проект, написанный на Laravel и выполненный в рамках грейдирования по профессии «Бэкенд разработчика» в HTML Academy.
Проект полностью работает при локальном запуске через `php artisan serve`.

## Функциональность проекта

Проект реализует полный набор серверной логики социальной платформы:

- Регистрация и авторизация с валидацией
- Профили пользователей: показ на странице никнейма пользователя, а также его аватара; кнопки для отправки сообщения пользователю и подписки на него; отображение постов выбранного пользователя; публикации, которые понравились последнему; а также его подписки на другие профили
- Создание постов разных типов: text, quote, link, photo, video
- Загрузка и обработка файлов: аватары, изображения постов
- Лента активности с фильтрацией по типу контента и логика подписки на пользователей
- Лайки и подсчёт активности, система комментариев, и репостов
- Раздел «Популярное» с сортировкой по популярности, лайкам и дате, а также фильтрацией по типу контента и пагинацией между страницами
- Раздел «Сообщения», позволяющий отправлять сообщения другим пользователям, а также просматривать входящие сообщения с индикатором непрочитанных
- Раздел поиска по сайту с разделением по типу контента
- Уведомления о новых подписчиках и новых постах пользователей, на которых подписан текущий
- Очереди для отправки уведомлений (email)
- Интеграция с Mailpit для тестирования писем
- Валидация всех форм согласно требованиям ТЗ
- Eloquent‑модели и связи
- Миграции и сидеры
- Feature‑тесты для ключевых частей функционала
- Корректная обработка ошибок и HTTP‑кодов
- Строгая структура проекта согласно критериям HTML Academy

Проект выполнен в соответствии с техническим заданием и критериями грейдирования HTML Academy.

## Технические детали реализации

Проект приведён к единым стандартам качества кода и тестирования.

### PHPCS (PHP CodeSniffer)
Код проекта приведён к стандарту PSR‑12 с помощью PHPCS.  
Использовались правила для единообразия форматирования, читаемости и структуры кода.

### Psalm
В проект был добавлен статический анализатор Psalm.  
Однако его использование было признано избыточным для учебного задания, так как:

- Laravel активно использует магию фреймворка  
- Psalm выдавал ложные срабатывания  
- исправления могли привести к нарушению рабочей логики

Поэтому Psalm был добавлен, но **не применялся в финальной версии проекта**.

### Тестирование
В проекте используются Feature‑тесты для проверки ключевых сценариев.

При тестировании применяются:

- моки — для подмены зависимостей и поведения сервисов  
- стабы — для имитации внешних вызовов  
- фейковые драйверы Laravel (Storage::fake(), UploadedFile::fake(), Http::fake() и др.)  
- фабрики — для генерации тестовых данных

Тесты покрывают:

- регистрацию  
- авторизацию  
- создание постов  
- ленту активности  
- подписки  
- лайки
- комментарии
- репосты
- логику отображения популярного контента
- логику сообщений
- логику поиска

### Стандарты разработки
- строгая структура контроллеров, моделей и сервисов  
- использование Eloquent‑связей  
- валидация через FormRequest  
- корректные HTTP‑коды  
- обработка ошибок  
- единообразие нейминга и структуры файлов

## Установка и запуск

### 1. Установка зависимостей
composer install

### 2. Настройка окружения
Скопировать `.env.example` → `.env`  
Указать параметры подключения к MySQL.

### 3. Генерация ключа
php artisan key:generate

### 4. Миграции
php artisan migrate

## Сидеры (обязательно)
Для корректной работы проекта необходимо создать типы постов.  
Без сидеров невозможно создать пост, так как валидация требует существующий тип.

### Запуск сидеров:
php artisan db:seed

Сидеры создают:
- типы постов (text, quote, link, photo, video)
- тестовые данные (опционально)

## Storage
Перед отправкой проекта папки `storage/app/public/*` очищены и оставлены пустыми.  
Laravel автоматически создаёт файлы при загрузке аватаров и изображений.

### Симлинк:
php artisan storage:link

## Почта (Mailpit)
Для тестирования уведомлений можно использовать Mailpit.

### Запуск Mailpit:
.\mailpit.exe

### Настройки в `.env`:
MAIL_MAILER=smtp  
MAIL_HOST=127.0.0.1  
MAIL_PORT=1025  
MAIL_USERNAME=null  
MAIL_PASSWORD=null  
MAIL_ENCRYPTION=null  

Интерфейс Mailpit: http://localhost:8025

## Очереди (уведомления отправляются через очередь)

Уведомления в проекте **не отправляются напрямую**.  
Каждое уведомление ставится в очередь и обрабатывается воркером.

### Запуск воркера:
php artisan queue:work

Без запущенного воркера уведомления **не будут отправлены**, что является нормальным поведением проекта.

## Docker (Windows)
При запуске проекта через Docker Desktop на Windows могут возникать проблемы с:
- отображением файлов из `storage`
- рендерингом Blade‑шаблонов (ошибка tempnam())
- симлинками `public/storage`

Это связано с особенностями Docker volumes и файловой системы Windows.

### Важно:
Локальный запуск (`php artisan serve`) работает корректно.  
Рекомендуется использовать именно его.

---

### Особенности запуска тестов на Windows

При запуске большого количества тестов подряд в среде Windows может возникать
фатальная ошибка, связанная с особенностями работы PHP и файловой системы при
массовом создании временных данных и обработке тестовых файлов.

Это не связано с логикой проекта и не является ошибкой реализации.  
Все тесты проходят корректно при запуске по отдельности или небольшими группами.

На других операционных системах или в других средах поведение при данной операции неизвестно.
